## 1. Общая структура программы

Программа реализует интерактивный справочник для работы с динамической
C-строкой. Вся логика вынесена в чистые функции (`str_ops.h` / `str_ops.cpp`),
не выполняющие ввод/вывод самостоятельно (за исключением `str_print`, которая
по заданию семейства B как раз обязана печатать строку). Память управляется
вручную через `new[]` / `delete[]`, после удаления указатель обнуляется.

| Файл | Назначение |
|---|---|
| `str_ops.h` | интерфейс библиотеки функций |
| `str_ops.cpp` | реализация функций, алгоритм варианта (КМП) |
| `main.cpp` | текстовое меню, ввод/вывод, время жизни `src` |
| `tests/test_variant.cpp` | 22 юнит-тестов (Google Test) |

Меню:

```
1. Ввести строку
2. Напечатать
3. Длина
4. Скопировать в буфер и напечатать
5. Алгоритм варианта
0. Выход
```

## 2. Используемые алгоритмы и структуры данных

### 2.1 Динамический ввод строки произвольной длины — `input_learn`

Поскольку `std::string` запрещён, строка читается посимвольно
(`std::cin.get`) в буфер `char*`, который **удваивается** (`capacity *= 2`),
когда места не хватает — классическая стратегия геометрического роста
(как во внутренней реализации `std::vector`/`std::string`, только вручную).

**Асимптотика:**
- Амортизированное время добавления одного символа — **O(1)**.
- Суммарное время чтения строки длины *n* — **O(n)**, несмотря на
  периодические перевыделения памяти (сумма геометрической прогрессии
  размеров буфера ограничена `O(n)`).
- Память: в худшем случае буфер занимает до ~2*n* ячеек непосредственно
  перед финальным копированием в `str_alloc`, которое ужимает строку до
  точного размера `n + 1`.

### 2.2 `str_len` — длина строки

Линейный проход до символа `'\0'`.

- **Время:** O(n), где *n* — длина строки.
- **Память:** O(1) дополнительной памяти.

### 2.3 `str_alloc` / `str_copy` — создание независимой копии строки

`str_alloc` вызывает `str_len` (O(n)), выделяет `new char[n+1]` и копирует
содержимое через `str_copy`.

- **Время:** O(n) + O(n) = **O(n)**.
- **Память:** O(n) — под новую копию.

### 2.4 `str_count_words` — подсчёт слов

Один линейный проход по строке с отслеживанием состояния «внутри слова /
вне слова» (переход «не-слово → слово» увеличивает счётчик). 

- **Время:** **O(n)**, один проход, без заглядывания вперёд.
- **Память:** O(1) — один флаг состояния и счётчик.

### 2.5 `str_find_substr` — поиск подстроки (алгоритм Кнута–Морриса–Пратта)

Алгоритм варианта. Наивный поиск подстроки имеет асимптотику **O(n·m)** 

**Шаг 1. Префикс-функция (`prefix`)**

Для каждого индекса `i` образца вычисляется длина наибольшего
собственного префикса подстроки `p[0..i]`, совпадающего с её суффиксом.

```
prefix("aaab") = [0, 1, 2, 0]
```

- **Время:** **O(m)**, где *m* — длина образца. Указатель `k`
  (длина текущего совпадения) на каждой итерации увеличивается не более
  чем на 1, а уменьшается только через переходы по уже вычисленным
  значениям `pi[]` — суммарно амортизированно O(m).
- **Память:** O(m) — массив `pi[]`.

**Шаг 2. Основной проход (`kmp`)**

Текст сканируется один раз; при несовпадении символа позиция в образце
«откатывается» по значениям префикс-функции вместо повторного
прохода по тексту.

- **Время:** **O(n)**, где *n* — длина текста (по той же логике
  амортизации, что и для `prefix`).
- **Память:** O(1) дополнительно к `pi[]`.

**Итоговая асимптотика КМП:**

| Этап | Время | Память |
|---|---|---|
| Построение `pi[]` | O(m) | O(m) |
| Поиск по тексту | O(n) | O(1) |
| **Итого** | **O(n + m)** | **O(m)** |

## 3. Управление памятью

Все динамические выделения (`new[]`) сопровождаются ровно одним `delete[]`
на каждом пути выполнения функции:

| Выделение | Где освобождается |
|---|---|
| `src` (строка пользователя) | `str_delete` в `case 1` (при повторном вводе) и `case 0` (выход) |
| `searchString` | `str_delete` в конце `case 5` |
| `buf` в `input_learn` | `delete[]` после копирования в `str_alloc` или при ошибке ввода |
| `copy` в `case 4` | `str_delete` сразу после печати |
| `pi[]` в `kmp` | `delete[]` на единственном пути выхода из функции |

Указатели после удаления обнуляются (`str_delete` принимает `char*&`),
что предотвращает повторное использование освобождённой памяти
(use-after-free) и двойное освобождение (double-free).

## 4. Тестирование

Написано **22 юнит-тестов** на Google Test (требование методички — не
менее 10), покрывающих:

| Функция | Тестов | Проверяемые аспекты |
|---|---|---|
| `str_len` | 2 | пустая строка, строка с пробелами |
| `str_copy` | 2 | копирование, перезапись более длинной строки |
| `str_alloc` | 3 | содержимое, пустая строка, независимость копии от оригинала |
| `str_delete` | 2 | обнуление указателя, безопасность на `nullptr` |
| `str_print` | 2 | обычная строка, `nullptr` |
| `str_count_words` | 6 | пусто, несколько слов, пробелы в начале/конце/между словами |
| `str_find_substr` | 8 | начало, середина, не найдено, образец длиннее текста, перекрывающийся префикс (худший случай для наивного поиска), самое левое вхождение, пустой образец, корректность `out_pos` при неудаче |

Тест `OverlappingPrefixPattern` (образец `"aaab"` в тексте `"aaaaaab"`)
специально проверяет именно тот случай, где наивный поиск подстроки
работал бы медленно (O(n·m)), а КМП — эффективно, благодаря
префикс-функции.
